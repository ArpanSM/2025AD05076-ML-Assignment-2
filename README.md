# ML Assignment 2: Credit Default Classification

## Problem statement

This project compares classification algorithms for predicting whether a credit-card client will default on the next payment. The same stratified holdout test data is used for every model, and the trained pipelines are exposed through an interactive Streamlit application.

## Dataset description

The project uses the [UCI Default of Credit Card Clients dataset](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients). It contains 30,000 client records and 23 numeric predictors after the identifier column is removed. The binary target is `default_payment_next_month`, where 0 means no default and 1 means default. This satisfies the assignment minimum of 12 features and 500 instances.

The source dataset is downloaded and converted by `train_models.py`. The application uses only the labeled held-out rows in `test_data.csv`, which keeps the Streamlit deployment lightweight.

## Models used

The assignment text says that six models are required but explicitly names five models. To satisfy the repeated six-model requirement, this project implements the five named models plus Gradient Boosting and documents that choice here.

All models are evaluated on the same 20% stratified test split. Precision, Recall, and F1 use weighted averaging because the target classes are imbalanced. The reported metrics are Accuracy, ROC AUC, weighted Precision, weighted Recall, weighted F1, and Matthews Correlation Coefficient.

### Observations about model performance

The observations below are based on the generated comparison table.

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Provides the weakest overall result on this split, with the lowest accuracy, F1, and MCC. Its linear boundary does not capture the relationships as effectively as the tree-based models. |
| Decision Tree | Improves on Logistic Regression across all metrics, but remains below the ensemble models. The depth and leaf constraints help limit overfitting. |
| kNN | Achieves the second-highest accuracy and recall, showing that local neighborhoods are useful after scaling. Its AUC and MCC are lower than the ensemble models. |
| Naive Bayes | Produces a middle-range result with good accuracy, but its conditional-independence assumption limits ranking quality and MCC on these correlated features. |
| Random Forest (Ensemble) | Has the highest MCC and the second-highest AUC, indicating the strongest balanced correlation with the target and robust performance across classes. |
| Gradient Boosting | Achieves the highest accuracy, AUC, precision, recall, and F1. It provides the best mean rank across all six metrics, although Random Forest has a slightly higher MCC. |
| **Overall Winner** | **Gradient Boosting** is the overall winner by mean rank across the six metrics (1.167), followed by Random Forest (2.167). |

## Project files

- `app.py` — Streamlit interface with CSV upload, model selection, metrics, confusion matrix, classification report, and comparison view.
- `train_models.py` — dataset preparation, reproducible training, evaluation, and artifact generation.
- `metrics.py` — shared implementation of the six evaluation metrics.
- `test_data.csv` — labeled held-out test data used by the app.
- `model/` — saved pipelines, metadata, and generated metrics.
- `requirements.txt` — local and Streamlit Community Cloud dependencies.

## Running locally

1. Create and activate a Python virtual environment.
2. Install dependencies with `pip install -r requirements.txt`.
3. Run `python train_models.py` once. This downloads the UCI source data, trains all six models, creates `test_data.csv`, and saves artifacts in `model/`.
4. Start the app with `streamlit run app.py`.

The app accepts a CSV containing the 23 predictor columns and, for evaluation, the `default_payment_next_month` target column. The bundled test file can be used without uploading another file.

## Deployment

Push `app.py`, `requirements.txt`, `README.md`, `test_data.csv`, and the generated `model/` directory to GitHub. In Streamlit Community Cloud, select the repository, the main branch, and `app.py` as the entry point. Test the deployed link before adding it to the final PDF.

## Reproducibility and limitations

The split seed is fixed at 42 and the same test rows are used for every model. The app performs inference only and does not retrain models. Results depend on the selected holdout split and the model hyperparameters; no claim is made that these settings are globally optimal.
